# 设计素材收录

目标仓库：https://github.com/Cinnnnnnndy/look-and-feel ，分支 main。先确认操作的是该仓库，读取 entries/_template.md、data/entries.js、SUMMARY.md 和 docs/积累经验.md；以仓库当前结构为准。

## 确认对象与证据

- 只有产品首页链接且意图未明确时，先问分析官网还是产品本身；“官网落地页”只用于营销站点。已明确的答案不重复询问。
- 询问是否已有分析或报告，并检查现有条目。已有报告时写摘要、标注来源并链回原文，只补缺失维度。
- 需要登录或网络拦截时，请用户提供截图或放到 /Users/cindy/Desktop/积累。建议主视图、关键功能、展开/hover、空状态。没看到图不写视觉分析。
- 字体名、字号、字重、hex 色值优先由页面样式或设计源确认；截图估测标注“估测”，无法确认写“待确认”。静态图不能证明动效或交互行为，推断必须标明。
- 每份素材独立线程；启动页与结构修改归入“素材库启动页与结构”。普通收录可更新索引和增加必要场景；不顺带重做启动页。创建或向其他线程发送消息遵循当前环境的用户授权要求。

## 写条目

复制 entries/_template.md 到 entries/<YYYY>/<YYYY-MM-DD>-<产品名>/README.md；日期使用用户时区收录当天，截图放同目录。保留历史条目，再次收录建立新日期条目并互链。

必须包含产品名、链接、收录日期、场景、平台、标签、素材来源，以及：
- 视觉风格：基调、配色 hex、形状语言、深度（阴影/描边/材质）。
- 字体：具体字体、字号阶梯、字重；注明证据和不确定项。
- 层级：页面信息架构、布局分区、组件内信息顺序、层级表达手法。
- 交互：流程、反馈、状态、快捷操作；用户点名的功能单独成节。
- 演变时间线、可借鉴和待商榷结论。无历史证据时注明本次为基线，不编造演变。

只写可比较的细节，避免“简洁大方”等空话。已有报告摘要模式仍保留这些维度；未覆盖的写明原文未覆盖或待补证据。

## 更新索引与归纳

1. 在 window.LF_ENTRIES 顶部加入 product、scene、title、summary、link、date、platform、tags、path、cover。path 是仓库相对条目目录；cover 是真实图片相对路径，无图可省略，不能引用不存在的文件。
2. scene 使用 window.LF_SCENES 的已有值，无合适值才新增。
3. SUMMARY.md 增加新模式及出处、收录表行，更新实际条目数和日期；在“演变与对比”补同产品纵向变化和跨产品横向对比，比较同类触点。无可比证据时说明缺口，不强造结论。

## 检查与发布

- 检查图片/相对链接可达、条目无重复、日期与 scene 一致、JavaScript 语法正确、统计匹配；预览卡片与场景筛选。
- 在本仓库既定的直接发布授权下，提交本次相关文件并 push 到 main。保留其他人的改动；并发冲突先重新读取合并，禁止强推覆盖。
- 有素材或启动页变化时，刷新 https://claude.ai/artifact/WvYqbBT6mQ65Pd34EiaL4d ：将 assets/style.css 和 data/entries.js 内联到 index.html 对应引用位置，保持脚本执行顺序，图片通过 files 映射按仓库相对路径提供。
- 只有实际可用的发布能力才执行 artifact 更新。无法更新时交付单文件及图片映射并明确“预览未发布”，不要把 push 成功等同于预览已刷新。纯流程文档更新无需刷新素材预览。
- 完成后返回条目/文件链接、提交结果、预览状态，并提醒用户在本地素材库 git pull。
