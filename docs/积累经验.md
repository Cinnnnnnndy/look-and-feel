# 积累经验与收录流程

> 这份文档说明这个素材库怎么收录、怎么写分析、怎么归纳。新收录一条素材时照此执行。
> 整理于 2026-10-29，覆盖 Miro、FLOX、Cardeva、WayPilot、heypcb 五条收录的经验。

## 一、经验总结

1. **一份素材开一个线程。** 每个产品单独分析，互不干扰。启动页和仓库结构的改动统一放在一个专门的线程里。
2. **用固定模板，保证可比。** 每条都要写产品名、链接、收录日期。分析必须覆盖四块：字体（具体字体、字号阶梯、字重）、层级结构、视觉风格（配色写 hex、形状、深度）、交互。不写「简洁大方」这类空话，只写能拿来对比的细节。
3. **按固定流程走。** 写 `entries/年份/日期-产品名/README.md` 并放入截图，在 `data/entries.js` 加一条（带 `scene` 场景），更新 `SUMMARY.md`，push 到 `main`，再刷新预览页。
4. **按场景归类。** 启动页按产品场景筛选，比如开发工具、SaaS 仪表盘、官网落地页。遇到新场景就加一个。
5. **纵向和横向都要比。** SUMMARY 里既记录同一产品的演变时间线，也写跨产品对比。例如 heypcb 和 Miro 都是画布型工具，heypcb 和 WayPilot 都有 AI 输入框。
6. **先确认分析对象。** heypcb 那次一开始被当成官网分析，实际要的是编辑器本身。之后只给链接时，先确认是看官网还是看产品。
7. **已有的分析就复用。** 已经有报告的，在条目里写摘要并链回原文，不再重复写一份。
8. **素材靠 Cindy 来补。** 需要登录的产品、被网络拦截的站点抓取不到，要靠截图。截图越全（主视图、关键功能、空状态），分析就越扎实。

## 二、收录流程

### 1. 确认分析对象

- 只给了链接时，先确认要看的是**官网 / 落地页**还是**产品本身**（编辑器、仪表盘、App 内页面）。
- 页面需要登录或抓取不到时，直接说明，并请 Cindy 补截图。建议截这几处：主视图、关键功能、hover 或展开状态、空状态。
- 已经有现成报告或文章的，记下原文链接，之后摘要引用。

### 2. 写条目

- 目录：`entries/<YYYY>/<YYYY-MM-DD>-<产品名>/`，分析写在其中的 `README.md`，截图按 `01.png`、`02.png`… 命名，放在同一目录。
- 从 [`entries/_template.md`](../entries/_template.md) 复制。头部表格必填以下几项：

| 字段 | 要求 |
| --- | --- |
| 产品名 | 产品 / 应用 / 网站名称 |
| 链接 | 原始链接 |
| 收录时间 | 收录当天，`YYYY-MM-DD` |
| 产品场景 | 与 `entries.js` 中的 `scene` 一致 |
| 平台 / 标签 | iOS、Web、桌面等；标签用于启动页筛选 |

- 正文必须覆盖的维度：

| 维度 | 写到什么程度 |
| --- | --- |
| 视觉风格总览 | 一句话定性，以及气质、用色策略、形状语言、深度（阴影、描边、材质） |
| 字体 | 具体字体名（标题、正文、数字各用什么）、字号阶梯、字重与行高 |
| 层级结构 | 页面结构层级、界面布局层级、单个卡片内的信息层级，以及用了哪些层级手法 |
| 视觉要点 | 布局与栅格、色彩（写 hex）、图标与插画、质感（圆角、阴影、留白） |
| 交互设计点 | 核心流程、反馈与状态、动效与转场、手势与快捷操作、细节惊喜 |
| 演变时间线 | 能查到历史改版的就填。再次收录同一产品时，在这里追加 |
| 可借鉴 / 待商榷 | 各写几条具体结论，反例也要写 |

- 每条结论都要能拿去和别的产品比，比如「8px 控件圆角，1px 描边代替阴影」，而不是「简洁现代」。
- 是推断而不是从素材里直接看到的，要注明。抓不到原页面时，写清楚分析依据的是什么。

### 3. 更新启动页索引 `data/entries.js`

在 `window.LF_ENTRIES` 数组的**最前面**加一项：

```js
{
  product: "产品名",
  scene: "SaaS 仪表盘",          // 必须是 LF_SCENES 里的值，否则显示为「其他」
  title: "一句话主题",
  summary: "一句话结论，显示在卡片上",
  link: "https://…",
  date: "2026-10-29",
  platform: "Web",
  tags: ["仪表盘", "Bento"],
  path: "entries/2026/2026-10-29-产品名",
  cover: "entries/2026/2026-10-29-产品名/01.png", // 没有截图时可省略
},
```

遇到新场景时，先把它加进 `window.LF_SCENES`。数组的顺序就是启动页上的显示顺序。

### 4. 更新归纳 `SUMMARY.md`

- **视觉要点 / 交互设计点**：把新的规律放到对应小节，每条末尾用链接注明出处条目。
- **演变与对比**
  - *按产品的时间线*（纵向）：同一产品的历次改版和多次收录。
  - *跨产品对比*（横向）：与已收录的同类产品对比，比如同为画布型工具、同有 AI 输入框、同为仪表盘。
  - *行业趋势观察*：多个产品共同出现的方向。
- **收录索引**：表格里加一行。
- 更新顶部的「最近更新」日期和已收录条数。

### 5. 提交并推送

- 直接提交到 `main`，提交信息写明收录了什么、SUMMARY 补了哪些对比。
- 每收录一条就推送一次，不攒批。

### 6. 刷新预览页

- 预览页：<https://claude.ai/artifact/WvYqbBT6mQ65Pd34EiaL4d>
- 预览页是单文件版本：把 `assets/style.css` 和 `data/entries.js` 内联进 `index.html` 的 body 后，重新发布到同一地址。
- 有封面图时，发布时把图片按仓库里的相对路径一并带上（如 `entries/2026/2026-10-26-FLOX/01.png`），卡片才会显示封面。

## 三、收录前自检

- [ ] 分析对象已确认（官网还是产品）
- [ ] 头部表格包含产品名、链接、收录时间、场景
- [ ] 字体、层级结构、视觉风格、交互四块都有具体细节（字体名、字号、hex）
- [ ] `entries.js` 已加一项，`scene` 在 `LF_SCENES` 里
- [ ] SUMMARY 已补规律、纵横对比和索引行，日期与条数已更新
- [ ] 已推送 `main`，预览页已刷新


## 四、可复用 Skill 与执行边界

仓库内 Skill：[look-and-feel-collect](../.agents/skills/look-and-feel-collect/SKILL.md)。在本仓库使用 Codex 时，可输入“用 look-and-feel-collect 收录这个产品”，并提供链接、分析对象、截图或已有报告。移植到其他环境时复制完整 skill 文件夹，并确认目标仓库与发布授权。

- 每份素材独立线程；启动页和结构调整集中在「素材库启动页与结构」。普通收录按既定流程更新索引和必要的新场景。
- 开始时询问是否有已有分析；有则摘要并链回原文，仅补缺失内容。
- 登录或网络拦截导致无法查看时，请 Cindy 提供截图或放到 `/Users/cindy/Desktop/积累`。没看到图就不写视觉分析。
- 字体名、字号、字重、hex 优先依据页面样式或设计源；仅凭截图估测时标注“估测”，不能确认的写“待确认”。静态图中无法验证的动效和交互不写成已确认事实。
- 用户特别点名的功能单独成节。再次收录保留旧条目，新建日期条目并互链；无历史素材时记录本次基线。
- 发布前检查图片与链接、索引字段、场景值、条目数、JavaScript 语法，以及卡片和筛选显示。提交仅包含本次相关改动；并发更新先合并，不能强推覆盖。
- 预览单文件应在原 CSS/JS 引用位置内联内容并保持执行顺序；封面按仓库相对路径通过 files 映射提供。
- 若当前环境没有 Claude artifact 发布能力，交付单文件和图片映射并明确“预览未发布”；不能把 GitHub 推送成功当作预览刷新成功。仅修改流程文档或 Skill 时无需刷新素材预览。
- 完成后给出条目链接、提交结果与预览状态，并提醒 Cindy 在本地素材库执行 `git pull`。

维护时同步检查本页与 Skill，确保字段、路径、证据要求和发布步骤一致。
